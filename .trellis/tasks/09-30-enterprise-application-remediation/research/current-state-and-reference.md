# 现状研究与参考项目对照

## 1. 需求来源

源文件：`诉求确认-27日再标注 (1).docx`。

文档确认的业务范围不是单纯商品展示，而是：普通商品交易、处方饮片、就诊人/健康信息、推广关系、会员分级、奖励结算、提现、客户档案、内容轮播、数据报表、后台角色和第三方人工兜底。文档明确要求后台日常操作可执行，接口未接通时不能阻断人工处理。

关键规则包括：订单 30 分钟未支付取消、发货 7 天自动收货、处方有效期和一次使用、处方药除质量问题外不退换、推广客户首次归属、直接客户奖励、收货后 7 天奖励生效、每周结算、500 元提现门槛、销售人员可见名下客户的脱敏处方信息、管理员/药师敏感信息查看留痕。

## 2. 当前实现证据

### 小程序

- 页面清单已扩展到 20 个页面，但多个页面仍采用本地仓库或失败后静默回退，导致后台变更无法稳定反映到小程序。
- 首页此前只读取本地文章和轮播；文章详情缺少分类主题、绑定商品和跳转配置。
- 处方列表和商品详情没有统一的处方/药品数据契约；本地 JSON `require` 曾导致微信编译后模块找不到。
- 地址、会员申请、分享归属、tabBar 跳转和 API 合法域名属于跨层联调点，必须有真机/开发者工具验收。

### 管理后台

- 原有工作台把模块放在单个压缩组件里，商品和文章有少量表单，但订单、处方、销售、客户、轮播和数据菜单缺少成套的查询/详情/编辑/删除闭环。
- `EnterpriseModules.vue` 已加入独立模块工作区，但需要继续以同一模式覆盖所有诉求域，避免旧演示区与新接口区并存造成数据源分裂。
- 内容管理需要把文章和轮播拆成独立工作台；文章需要分类、推荐、商品绑定，轮播需要默认/自定义、裁剪、排序和启停。

### 服务端和数据库

- `BusinessService`、`OperationsService` 和控制器已具备不少接口，但请求体大量使用 `any`，缺少统一 DTO、分页、筛选和状态机约束。
- `MemoryStore` 是演示数据源；`PrismaSyncService` 曾只同步部分集合，容易产生重启丢数据和演示数据污染生产库的问题。
- 订单支付、库存批次/流水、处方归属、售后退款、奖励余额和提现需要统一事务与幂等策略。
- 内容数据已经增加文章推荐、分类、商品绑定、轮播模式和排序字段，并需要跟随 Prisma 迁移同步。

## 3. 参考项目研究

### litemall / nideshop

- 小程序按业务拆分为首页、分类、商品、搜索、购物车、结算、支付、订单、地址、用户中心、专题/内容等独立页面。
- 商品购买链路有专门的地址、结算、支付结果和订单详情页面；后台菜单按会员、商城、商品、推广、系统、配置和统计拆分。
- 可借鉴：业务边界清晰、每个流程有独立页面和接口，不把所有状态塞进首页或一个通用列表。

### wechat-app-mall

- 后台/小程序对推荐商品、轮播、活动、会员、推广订单和内容使用独立 API 读取；页面数据不是硬编码在模板中。
- 购物车、地址、订单、物流、发票和推广模块有单独的数据加载和错误提示。
- 可借鉴：后台运营数据和小程序展示数据共享 API，内容/轮播更新后不需要重新编译小程序。

### tdesign-miniprogram / vant-weapp

- 组件库强调表单校验、列表空态、弹窗确认、上传组件和反馈状态；适合统一老年用户的大字、按钮和错误提示体验。
- 可借鉴：上传和裁剪必须有明确尺寸提示、失败反馈和重新选择入口。

## 4. 企业标准差距矩阵

| 模块 | 当前主要差距 | 目标闭环 | 优先级 |
|---|---|---|---|
| 身份/权限 | 后台 token 流程和角色范围不完整 | 登录、角色、过期、越权拒绝、审计 | P0 |
| 商品/库存 | SKU、批次有效期、库存流水未形成完整后台 | 商品表单、规格、批次、盘点、上下架、审计 | P0 |
| 订单/支付 | 客户端可直接标记支付，支付记录不完整 | JSAPI 下单、回调验签、金额校验、幂等、退款 | P0 |
| 处方 | 归属/有效期/品种校验和文件链路不完整 | 就诊人、文件、审核、一次使用、过期拦截 | P0 |
| 推广/奖励 | 余额、归属、结算和转移规则存在演示逻辑 | 关系树、规则、台账、周结算、提现状态机 | P0 |
| 客户档案 | 查看、标签、授权和导出缺少统一入口 | 档案详情、标签筛选、敏感查看审计、导出 | P1 |
| 内容/轮播 | 增删改查、推荐、绑定商品、裁剪和小程序读取未完全闭环 | 内容工作台与公共内容 API | P1 |
| 售后/发票/物流 | 申请有接口，后台处理和小程序查询不完整 | 订单子流程、文件上传、状态、人工任务 | P1 |
| 数据/设置 | 统计和业务设置有硬编码或静态数字 | 可筛选报表、导出、配置真正驱动服务端 | P1 |
| 部署/持久化 | Prisma/迁移/密钥/合法域名存在环境风险 | readiness、迁移、回滚、数据一致性 | P0 |

## 5. Release blockers

1. 没有真实有效的后台身份会话时不能开放生产管理功能。
2. 没有支付商户配置和回调验签测试时不能声称支付闭环完成。
3. 没有真实 MySQL 迁移和持久化回归时不能把内存模式当生产数据源。
4. 处方、健康信息、推广奖励和宣传内容必须通过公司资质及合规确认。
5. 小程序真机必须使用备案 HTTPS 合法域名；本地 `127.0.0.1` 只用于开发者工具联调。
