# 企业应用全量整改与修复报告

## Goal

把当前“页面能打开、功能像演示壳”的微信小程序平台，整改为能被运营、药师、发货员、销售人员和管理员连续使用的企业应用。所有用户可见业务都必须有真实的数据来源、操作入口、表单校验、保存反馈、状态流转、权限边界和审计记录。

## Background

诉求文档确认了四条主线：普通商品交易、处方饮片服务、推广/会员奖励、客户健康档案；后台还必须支持商品、处方、订单、销售、用户、内容、数据和设置八类运营工作。互联网医院、发票、物流、短信等第三方未接通时，由后台人工处理，但主流程仍须可用。

当前仓库包含原生微信小程序、Vue 管理后台、NestJS API 和 Prisma/MySQL 模型。现状存在演示数据与生产数据混用、前后端字段不一致、后台操作缺表单或查询、支付/处方/奖励状态不完整、持久化不同步等问题。

## Requirements

### R1. 统一数据和权限边界

- 建立用户、商品/SKU、库存批次、订单、支付、处方、售后、发票、推广关系、奖励、提现、文章、轮播、客户档案和审计的明确数据契约。
- 后台角色至少区分管理员、药师、发货员；销售只能看自己的归属范围；会员不能查看客户处方信息。
- 敏感查看、审核、导出、归属调整、奖励调整和提现操作必须留痕。

### R2. 小程序交易闭环

- 登录、手机号、地址、就诊人、商品列表/详情、购物袋、结算、支付、订单、物流、确认收货、售后和发票均可完成真实状态闭环。
- 金额、运费、库存、处方有效期和订单归属由服务端校验；客户端不能直接决定支付成功。
- 处方订单必须校验用户归属、药品匹配、有效期和一次性使用；普通商品售后遵循七天规则，处方商品只允许质量问题售后。

### R3. 处方服务

- 支持互联网医院处方、线下上传处方、后台人工录入和药师审核。
- 处方绑定实名就诊人，记录审核人、审核时间、有效期、凭证和处方品种。
- 处方分类、状态、待支付入口和后台审核结果在小程序与后台保持一致。

### R4. 推广、会员和客户档案

- 支持销售人员由后台创建、会员申请审核、会员等级、销售人员→会员→客户的归属关系。
- 支持推广链接/二维码首次归属、解绑/转移、直接客户奖励、周结算、提现审核和财务导出。
- 客户档案包含基本信息、就诊人、健康信息、购买/处方记录、推广人、标签和授权记录。

### R5. 内容、推荐和轮播

- 文章支持七个默认分类、增删改查、草稿/发布、推荐、排序、商品绑定和跳转商城。
- 每个分类在小程序详情页有独立视觉主题；文章末尾可跳商品详情或商城。
- 轮播支持默认素材、自定义素材、固定比例裁剪、排序、启停、跳转目标和删除；后台保存后首页读取同一数据源。

### R6. 后台工作台

- 每个菜单都必须有列表、搜索/筛选、详情、创建/编辑表单、保存反馈、状态操作、空态和错误态。
- 商品支持价格、规格、上下架、库存批次/有效期和奖励规则。
- 订单支持状态筛选、客户/订单号查询、详情、发货、售后、退款、发票处理。
- 数据菜单支持按时间、板块、商品、推广人统计和 XLSX 导出。
- 设置中的运费、自动任务、提现门槛、推广规则和集成状态必须真正影响运行逻辑。

## Constraints

- 继续使用现有原生微信小程序、Vue 3、NestJS、Prisma/MySQL 技术栈，避免引入与现有架构无关的重型框架。
- 本地联调允许 `127.0.0.1`；生产必须切换备案 HTTPS 域名并通过微信合法域名校验。
- 第三方账号、支付商户号、医院/发票/物流接口和资质仍由公司提供；未提供时保持人工适配器，不伪造真实成功状态。

## Acceptance Criteria

- [ ] 新用户可以从小程序完成登录、地址、普通商品下单、支付回调、发货、物流、确认收货、售后和发票申请。
- [ ] 处方用户可以绑定就诊人、提交/查看处方、审核后按有效期购买一次；错误用户、过期处方和药品不匹配请求被拒绝。
- [ ] 销售人员和会员的归属、客户、奖励、周结算和提现数据可追溯；越权访问返回拒绝。
- [ ] 后台八个业务菜单均可查询、创建/编辑、查看详情和执行状态操作；操作后列表和统计刷新。
- [ ] 管理员新增文章/轮播后，小程序文章列表、文章详情和首页轮播能读取同一条记录；推荐和商品跳转可验证。
- [ ] Prisma schema、迁移、内存演示模式和 API DTO 对同一字段保持一致；重启不丢失业务数据。
- [ ] 服务端 lint/build、后台 build、小程序清单/脚本检查和关键 API/浏览器验收全部通过。

## Out of Scope

- 本任务不代替公司完成微信支付商户开通、互联网医院协议、处方药销售资质、健康信息合规审批或第三方生产账号申请。
- 第三方真实接口在没有凭证时只实现可替换适配器和人工任务，不虚构供应商返回。

## Deferred Decisions

- 运费阈值、各品种奖励比例、会员晋级和解绑口径仍按后台可配置项实现；最终财务/业务确认后填入配置。
- 健康授权文案、处方留存期限、发票类型和供应商选择由公司确认后替换文案或适配器配置。
